# Pliette：模型专属动作指导书与受限实时参数生成开发 Spec

版本：1.0  
日期：2026-09-09  
交付对象：在 Pliette 代码仓库中工作的开发 Agent  
文档性质：可执行的增补规格；本文未实施代码、未标定新角色、未测得新的动作质量或延迟。

**目标：为每个真实 Spine 角色建立经过实测的“身体使用说明书”，让运行时 LLM 理解该角色的骨架、参数含义、可用姿态与组合边界，在允许范围内生成新的短动作关键帧；由程序负责验证、编译、调度和逐帧播放。**

本文统一使用正式名称 **Spine**。本文中的“模型”若未注明，指角色资产；“LLM”指语言模型。

## 0. 给开发 Agent 的执行约定

1. 先读当前仓库的 `AGENTS.md`、迭代记录、现有 `RigProfile`、`MotionDraft`、编译器、调度器及播放器。按实际代码复用模块，不凭旧文档重新建一套项目。
2. 本任务集中实现动作指导书及其生成、使用、验证流程。沿用项目技术栈；旧 Spec 为 TypeScript / Vite / 官方 Spine Runtime，当前代码若已合理演进，保持现状并记录接口映射。
3. 先正确播放真实角色的原动画，再评价新参数。不得重写 Spine 蒙皮、裁剪、Deform、绘制顺序、约束求解或简化渲染器来替代官方结果。
4. 开发 Agent 可以执行资产检查、探针、录像、规则提炼和有证据的配置确认；每条结论要注明依据。运行时 LLM 只能输出动作候选，不能修改指导规则、控制器实现或运行时事实。
5. 普通常规选择与可逆修复继续自主完成。缺少角色、匹配的导入工具或 LLM 服务时，完成可独立推进的工作，准确列出阻塞；不以反复等待用户确认代替实施。
6. 本文的代码与 JSON 片段是协议说明，示例数值不是任何真实角色的已验收范围。不得把示例配置复制后标记为 `verified`。

## 1. 与既有方案的关系和验收目标

### 1.1 本次调整

| 既有设计 | 本次要求 |
| --- | --- |
| `RigProfile` 保存语义绑定、坐标和范围 | 扩展为有证据的角色控制档案，并从中生成模型专属说明书 |
| `Author` 主要在离线实验室创作 | 增加受限在线创作通路；先在 Lab 验证，再按角色、视图、动作域启用 |
| 运行时主要 `Select / Tune` | 保留；同时允许 LLM 输出新数值关键帧、节奏和合法组合 |
| 约束、参数说明和案例分散 | 使用共同的结构化来源生成说明书和校验配置，避免两者漂移 |
| 单角色绑定验证 | 先把主角色做透，再用第二个实际不同骨架检验适配机制 |

本节更新旧 `Pliette_Spec_v1.0.md` 中“运行时以选择、调参为主”的限制，不撤销官方运行时、属性所有权、接触依赖、真实录像等要求。若当前仓库接口不同，提交兼容迁移表，不并存两套同义协议。

### 1.2 必须保留的能力

- LLM 能在登记的控制范围内创作从未保存为 Preset 的数值曲线。
- 同一请求在不同角色上得到符合各自骨架的参数，而非照搬骨名、角度正负或数值。
- 支持多个部位并行；组合是否合法由实际属性、父级影响、约束与接触共同决定。
- 指导书需要提高首次生成质量，不能以人工修好后的录像冒充首轮效果。
- 没有可靠在线生成结果时，保留已有动作或基础状态；将失败明确记录，不把回退动作算作生成成功。

### 1.3 本轮不扩张的内容

不引入 ARDY、成人动作重定向、通用自动绑骨、全量动作数据库、额外大型视觉模型、LLM 微调、多引擎兼容平台或新的人格系统。新增骨骼、重绘素材、补复杂 IK 属于独立资产工作，不能靠指导文档假装已经获得这些能力。

## 2. 总体结构：共享规则 + 角色档案 + 当前状态

指导书采用类似 Lorebook 的分条组织和按需装配方式，但控制规则不能依赖关键词偶然命中。

| 部分 | 主要内容 | 装配方式 |
| --- | --- | --- |
| 共享基础规范 | 输出协议、单位约定、有限关键帧、错误响应、不可改写的事实 | 每次必带精简版 |
| 当前角色档案 | 骨架特点、控制器映射、实测效果、姿态与美术能力 | 每次带身份与摘要；相关章节必带 |
| 依赖与组合规则 | 争用属性、祖先影响、IK、接触、互斥条件 | 按开放控制器的依赖闭包确定性装配 |
| 动作经验 | 成功案例、反例、修正原因、风格规律 | 在预算内按相关性选取 |
| `RuntimeContext` | 当前姿态、视图、Skin、基础动画相位、占用、接触和请求时钟 | 每次由程序提供新快照 |

推荐复用现有模块，只补三个职责：

| 职责 | 实现位置建议 | 输出 |
| --- | --- | --- |
| 角色标定与证据管理 | 扩展 Asset Inspector / Rig Adapter / Motion Lab | 已标定 `RigProfile`、探针记录 |
| 指导书构建与上下文装配 | 新增小型 Guide Builder / Context Builder | 可阅读 Markdown、精简请求上下文 |
| 候选验证和受限在线接入 | 扩展 Motion Compiler / Scheduler | `CompiledMotion` 或结构化诊断 |

离线过程：检查资产，完成控制探针和组合验证，将证据写入档案，构建指导书。

在线过程：取当前档案和状态，装配上下文，生成完整短动作候选，验证并编译，重新检查当前状态后提交播放。逐帧渲染循环不等待网络或 LLM。

## 3. 每个角色必须拥有独立的骨架说明

### 3.1 档案身份与适用范围

档案至少绑定下列信息：

| 字段 | 含义 |
| --- | --- |
| `modelId / profileId / profileRevision` | 角色、档案及不可变修订标识 |
| `assetDigest` | 由源骨架、atlas、实际纹理内容及清单计算的内容摘要 |
| `runtimeRef` | 导出版本、官方运行时 major.minor、锁定提交或包版本、适配器版本 |
| `viewId / skinId / orientationVariant` | 已验证视图、Skin、镜像或朝向变体 |
| `referencePoseId / referencePoseDigest` | 参数参考姿态，不能仅写“初始姿态” |
| `heightUnits / coordinateConvention` | 固定标定身高、单位、局部与场景空间约定 |
| `controls / rules / evidenceRefs` | 可用控制器、规则和实际验证证据 |
| `profileDigest` | 以上控制相关定义的确定性摘要，用于上下文、缓存和候选绑定 |

资产、Skin、参考姿态、控制映射或规则改变后，旧验证范围不能自动继承。允许复用证据的情况必须明确列出受影响项并重验；单纯换文件名不代表新角色，骨名相同也不代表可共用档案。

模型切换时使旧请求和旧候选失效。不同角色的 MotionDraft 不直接互播；跨角色复用动作意图和设计经验，数值必须经目标角色重新生成或明确转换并验收。

### 3.2 静态检查和行为标定分开记录

可静态提取：骨名、父节点、setup transform、当前版本的变换继承设置、Slots、Attachments、Skin、约束及其依赖、动画时间线写入对象。

必须实测或检查画面：节点对应什么部位、正负方向的视觉效果、参数是否被约束覆盖、可接受幅度、接触关系、姿态是否符合原画。

骨骼长度可能缺省，零长度节点也可能是有效控制节点；不能用长度或名称直接推断人体骨架。Spine 的导出结构和版本字段应按目标版本解析，不能将现行 JSON 示例无条件套在旧资源上。[Spine JSON 格式说明](https://esotericsoftware.com/spine-json-format)

### 3.3 角色说明书的固定章节

每个角色的生成文档必须具备以下章节，内容缺失时标记 `unknown / unverified / unsupported`，不得补写猜测值：

1. **身体结构摘要**：大头短肢比例、当前姿态、完整身体还是半身、可用视图、素材上限。
2. **骨架拓扑与关键关系**：真实层级；身体部位之间是父子、兄弟还是约束连接；只展示任务相关子图，并提供完整索引。
3. **控制器字典**：每个语义控制器对应哪些真实骨骼、Slot 或约束；如何给数值；正负方向的可视解释。
4. **参考姿态与坐标**：哪个参考姿态、角色左右、位移空间、角度偏移和身高换算。
5. **作用链**：直接写入什么，间接影响什么；哪些原动画或约束会覆盖它。
6. **已标定范围和条件**：在什么姿态、视图、Skin、基础动画相位、幅度及速度范围内验收过。
7. **组合与接触规则**：左右手、头身、腿部支撑、口型与整脸附件等关系。
8. **设计案例与反例**：参数、画面、原因和适用条件，保留最初失败版本。
9. **能力缺口和替代策略**：缺少独立手指、嘴型、背面、弯肘等能力时如何响应。
10. **证据与版本**：原始资产摘要、探针、录像、评审者、日期、已验收范围。

### 3.4 单个控制器必须解释到的粒度

| 字段组 | 必须提供的信息 |
| --- | --- |
| 身份与类型 | `controlId`、语义部位、`localFk / ikTarget / slotState / composite` |
| 输入 | 数据类型、单位、维数、参考值、正负效果、默认值 |
| 绑定 | 原节点名、属性、符号或映射表、依赖、求解阶段 |
| 范围 | 数值合法域、已验证域、速率与时间限制、适用条件 |
| 所有权 | `writes`、`dependsOn`、受影响附件、资源与接触依赖 |
| 行为 | 一句话解释调大、调小和归零分别看起来怎样 |
| 证据 | 原始探针输入、最终属性采样、对应画面、验收状态 |

“控制手臂，范围 −90°～90°”不满足要求。说明必须能回答：这是上臂还是整臂，绕什么局部轴，相对哪个角度，受不受 IK 影响，是否带动衣袖，抬到什么程度轮廓开始失真。

标定时同时生成带部位标注的参考图和正、负变化对照图，供开发 Agent 检查。在线默认使用文字和结构化说明；若所用 LLM 支持图像，可以附少量固定参考图，但不能让纯文本模型必须依赖看图才能理解参数。

### 3.5 不同骨架的适配规则

| 实际结构 | 给 LLM 的说明及开放方式 |
| --- | --- |
| 上臂、前臂分段且可独立驱动 | 分别标定；开放各自局部参数及联动约束 |
| 整条手臂只有一个有效节点 | 只开放整臂姿态；弯肘能力记为缺失 |
| 手臂或腿被 IK 控制 | 优先开放目标点；明确父空间、约束链和可达范围 |
| 头部与躯干是兄弟节点 | 倾身时头部不一定跟随；需要已验证的联动控制 |
| 头部是躯干子节点 | 躯干会改变头部世界姿态；避免重复补偿 |
| 一张 Attachment 同时包含眼睛和嘴 | 表情与口型可能争用整脸；不能假装是独立通道 |
| 左右不对称或存在负缩放 | 分别标定；禁止直接取反当作通用镜像公式 |
| Mesh 同时受多根骨骼权重影响 | 按实际权重和约束补充影响关系，不能仅看 Slot 的挂载骨骼 |
| 原动画依赖 Deform / draw order / 换附件 | 保留官方播放；新动作需声明兼容的基础状态，默认不生成这些底层曲线 |
| 缺少完整背面或特定姿态素材 | 限定视图或返回能力不足；镜像正面不等于背面 |

## 4. 参数语义与官方执行边界

### 4.1 向 LLM 开放什么

V1 开放登记的局部旋转、二维目标或局部位移、离散附件状态；缩放只对已验证的特定控制器开放。`composite` 必须引用已存在且有版本的确定性控制器，不能由 LLM 临时写实现代码。

V1 的 composite 通过登记的数值或固定维数向量输入暴露，其子控制器写集和联动映射预先确定；不接受 LLM 自由拼装控制器对象或新增计算公式。

用户目标仍通过数值曲线表达。`Select` 与 `Tune` 可以同时存在，但不能用“选中了 wave”替代 `Author` 的新曲线生成验收。

默认关闭任意骨名写入、世界矩阵、原始网格顶点、Deform、shear、任意 draw order、骨架层级和约束开关。确需开放时，先完成该属性的版本适配、标定和独立验收，再扩展白名单。

### 4.2 单位和参考姿态

- 旋转统一用度，值表示相对档案指定参考姿态的偏移。参考姿态可以不同于 Spine setup pose，适配器负责转换为对应版本的 Timeline 语义。
- 位移使用固定角色身高 `H` 的比例；必须明确是父骨局部空间、skeleton 空间还是锚点空间。V1 优先只开放已绑定的父局部空间，场景目标由程序转换。
- `H` 在标定时固定，不随逐帧包围盒变化。纹理尺寸不是角色身高。
- 角色自己的左右与屏幕左右分开。镜像、朝向、Skin 变化须使用对应档案变体。
- 参数归零恢复其参考目标，不代表直接把原骨骼角度置零。实际入场从当前合成姿态混入，退出交回当前基础状态。
- 缩放是相对倍率；附件是离散枚举。若未来使用 0～1 归一化控制，需要附完整映射和证据，不能只换单位名。

### 4.3 控制权和求解关系

`writes` 描述真实执行属性；旧版 translate / scale 的 X、Y 若由同一 Timeline 整组覆盖，就按属性组仲裁。`dependsOn` 记录祖先、约束、接触及其他间接影响。

IK 开启时，不能把受约束链上的 FK 旋转和 IK 目标当作独立自由参数同时交给两个动作。改变 IK mix 需要经过专门验证的控制器和过渡策略。

每帧顺序沿用项目中经过验证的官方运行时流程：推进一次时间，应用基础与覆盖动画，写入已仲裁的程序控制或目标，再计算世界变换及约束，最后渲染。不可通过每帧累加偏移、随意修改共享 BoneData 或无条件重置 setup pose 制造漂移、串角色或混合跳变。[Spine Runtime Skeletons](https://esotericsoftware.com/spine-runtime-skeletons)

### 4.4 版本兼容

导出数据与官方运行时匹配 major.minor，并记录准确依赖。首次迁移优先解决同版本加载，不修改版本字符串冒充升级。当前文档中的方法名是职责说明，旧版本适配以其实际代码为准。[Spine 版本策略](https://esotericsoftware.com/spine-versioning)

若当前拉菲仍是旧 3.6 二进制，复用项目已验证的导入路径；若尚未解决，按旧 Spec 处理同版本官方导入或独立格式转换。不得用“已经读取骨名”代替“完整动画正确播放”。本轮不要求同时支持所有 Spine 历史版本。

## 5. Agent 如何标定并编写指导书

### 5.1 实施顺序

1. **基线**：中性背景、固定相机，完整播放相关原动画；检查贴图、Mesh、附件、裁剪及透明度。记录资产摘要。
2. **结构候选**：静态提取完整结构；依据名称、层级、权重和画面提出有限语义绑定，不自动宣布正确。
3. **单控制探针**：在隔离实例中，从同一参考姿态做小幅正负变化；采样最终属性和画面。首个步长由资产尺度决定，自动探针只在明确的小范围内递进。
4. **范围探索**：找到角色表现开始异常的区域，保留余量，形成当前条件下的已验证范围。探针失败立即停止该方向并恢复基线；不能随意扩大探索直至极端姿态。
5. **关系验证**：检查父子或兄弟联动、IK 覆盖、附件冲突、左右差异以及当前基础动画对控制的影响。
6. **组合验证**：按第 6 节优先测试共享祖先、接触、同属性争用和参数极值组合，不穷举所有排列。
7. **案例提炼**：保存第一次输出、失败画面、修正参数和理由；把可复用规律写回档案。
8. **构建与冻结**：生成说明书、请求精简版和校验配置，固定版本，再开始独立首轮生成评测。

### 5.2 证据记录

每项 `evidence` 至少包含：输入参数、参考姿态、Skin/视图、基础动画及采样时刻、环境与运行时版本、最终属性采样、录像或图片路径、观察结论、评审者、适用范围。

状态使用 `unknown / candidate / verified / rejected`。`verified` 仅表示其记录条件通过当前验收，不是对任意组合的保证。至少分别记录结构绑定、数值效果、视觉质量和组合范围的验证状态。

程序接受了字段、内部字典发生变化，都不足以证明参数有效。必须确认最终骨骼、锚点或可视部件按说明发生变化。仅将初值与终值都设成零的探针不构成有效性证据。

### 5.3 第二个角色的选择

先把主角色完成至可验证状态，再选一个具备至少一项真实结构差异的角色：骨名、setup 方向、父子结构、FK/IK、整臂/分段、表情组织等。优先选择已有可用且同运行时版本的资产，避免把跨版本适配混入本轮核心实验。

若没有第二个真实角色，可以用官方样例验证部分机制，但必须说明其类型与限制；同一角色改名、镜像或换皮不能作为“两个独立骨架”完整验收。第二角色材料不足时，标记多模型验收未完成，继续交付主角色结果。

## 6. 组合边界与规则来源

### 6.1 三种规则分别处理

| 类别 | 示例 | 执行方式 |
| --- | --- | --- |
| 确定性硬规则 | 有限数值、登记属性、时间递增、视图匹配、同属性所有权 | 程序强制执行 |
| 有条件的几何和动作规则 | 接触保持、手部可达、躯干带动头部、组合幅度 | 依赖明确实现和实测范围，程序检查；未实现就收窄开放范围 |
| 视觉与风格规则 | Q 版轮廓、重量感、可爱程度、合理遮挡 | 指导书案例与真实渲染验收 |

不能把“自然、不穿模、符合物理”注册成一个返回 true 的假校验器。二维部件重叠可能是正确遮挡，不能把所有相交像素视为错误。

### 6.2 必测组合

| 场景 | 核心检查 |
| --- | --- |
| 右臂挥手 + 左臂独立动作 | 真实写集是否隔离，基础动画是否仍覆盖 |
| 点头 + 躯干倾斜 | 头身拓扑与合成角度、轮廓和速率 |
| 行走 + 挥手 | 有可用步态时，手臂覆盖不破坏 IK、支撑与基础层 |
| 双手托腮 + 转头 | 手掌与脸的接触依赖，是否需要联动或先解除接触 |
| 眨眼 + 嘴型 | 独立属性还是整脸附件冲突 |
| 动作中断 | 只释放相关通道，当前姿态连续，退出不破坏接触 |

托腮等接触能力必须来自真实角色已有自由度和可验证实现。没有相应 IK 或联动控制器时，可限定为固定姿态、小范围联动，或报告不支持；不得现场生成一个通用求解器掩盖缺口。

### 6.3 规则的单一来源

扩展现有 `RigProfile / ControllerDefinition / ParameterDefinition`，不要另建内容重复的数据库。规则至少有 `ruleId`、类型、目标、条件、参数、严重程度、解释、证据引用和版本。

V1 使用有限规则类型，如 `range`、`rateLimit`、`requiresVariant`、`exclusiveWrite`、`requiresCapability`、`contactDependency`。每种类型必须有确定性解释器；不得执行来自文档或 LLM 的任意表达式代码。

同一结构化定义生成：给人的 Markdown、给 LLM 的精简片段、运行时校验配置。自然语言风格建议可作为规则旁的说明，但不自动变成硬约束。人工编辑生成的 Markdown 不应偷偷改变程序边界；修改应回到源定义并重新构建。

## 7. 请求上下文与指导书装配

### 7.1 每次请求的输入包

| 字段 | 最低要求 |
| --- | --- |
| `requestId / contextId` | 唯一请求与不可变快照标识，候选必须原样回传 |
| `profileRef` | 当前角色、修订、`profileDigest`、视图与 Skin |
| `goal` | 动作目的、指定手侧、必要动作和允许省略的装饰 |
| `runtimeState` | 当前姿态、基础动画及相位、相关控制值、所有者、接触、资源、当前转场 |
| `availableControls` | 本次允许输出的控制器；类型、单位、参考与映射说明 |
| `mandatoryRules` | 这些控制器和依赖闭包涉及的规则，不允许语义检索漏选 |
| `guideExcerpts / examples` | 相关动作设计经验、模型差异提示和少量正反例 |
| `generationBudget` | 时长、关键帧数、输出长度、截止时间等预算 |

不要把整个项目手册、所有骨名、所有皮肤和全部历史录像说明塞入每次请求。静态内容按 `profileDigest + 控制器集合 + 规则版本` 缓存，动态状态每次更新。最小规范和不可变档案身份不能被截断。

### 7.2 如何选章节

程序先给出本次可用的控制器集合，再按集合计算依赖闭包和必带章节；案例只在剩余预算中检索。首次可直接提供主角色全部少量已批准控制器，避免为几条控制引入向量库。

若动作需要未开放控制器，LLM 返回 `needs_context`，由程序判断能否构建新快照。不能让 LLM 写一个陌生骨名后自动获得访问权。在线默认不自动追加多轮上下文请求；开发实验可显式启用并单列延迟和调用次数。

依赖上下文放不进预算时，缩小开放控制器集合或返回上下文不足，不能删掉硬规则后继续。参数 Schema 或供应商的结构化输出能力可以减少格式错误，但不保证满足实际组合和视觉要求。

### 7.3 静态档案不能代替当前身体状态

必须区分“从 standing 可以挥手”与“现在右手被托腮动作占用”。当前姿态、资源和接触由程序给出，LLM 不能通过在输出中声明 `free=true` 或 `pose=standing` 改写它们。

拍快照时记录单调时钟、相关属性当前值及必要速度估计。坐标转换和目标解析由程序完成；不给 LLM 要求它凭屏幕坐标心算任意矩阵变换。

## 8. 输出契约：扩展现有 MotionDraft

### 8.1 三种响应

V1.1 响应使用严格判别联合，未知字段拒绝；响应包的 `requestId / contextId / profileDigest` 必须与服务端持有的请求相同。

| `status` | 字段 | 含义 |
| --- | --- | --- |
| `motion` | `draft` | 一段有限时长的新动作候选 |
| `unsupported` | `reasonCode / details` | 当前资产、姿态或能力确实不能表达 |
| `needs_context` | `requestedCapabilities / details` | 缺少必要说明；请求补充，不猜参数 |

`unsupported` 与 `needs_context` 不包含可执行曲线，也不允许夹带脚本。运行时可结束该次动作请求或按已登记策略回退，并记录实际结果。

### 8.2 MotionDraft 最小字段

| 字段 | 约束 |
| --- | --- |
| `schemaVersion` | 固定登记版本，如 `pliette.motion-draft/1.1` |
| `id` | 有长度限制的候选 ID；不直接用作文件路径 |
| `durationSec` | 有限正数，受请求预算约束 |
| `phases` | `prepare / stroke / hold / recover`；覆盖 [0, durationSec]、有序且不重叠，允许省略不需要的阶段 |
| `curves` | 至少 1 条；每条仅引用一个开放的 `controlId`，附 `keys`；同一 controlId 不重复 |
| `keys` | `timeSec / value / ease`；首键为 0，末键为 durationSec，时间严格递增 |

控制器决定 value 的判别类型：旋转为数值、二维平移为二元数组、缩放为登记维数、附件为允许的枚举字符串。省略控制器代表不申请写入，不代表把它归零。

`ease` 作用于当前键到下一键，末键不得携带无效 ease。V1 优先 `linear / smooth / stepped`；`smooth` 由编译器映射为固定、经过采样测试的有界缓动，不让 LLM 自由生成可能过冲的 Bézier。连续参数在线默认禁用 stepped，附件只允许 stepped。若项目已有验证充分的曲线格式，可保持旧格式并记录转换。

引用姿态、组合模式、真实 writes、依赖、混入混出、优先级、接触权和退出策略来自档案与调度器，不由生成模型任意声明。`draft` 只携带请求内被允许的创作数据。必要状态前提由程序推导；以后开放作者附加前提时，只能增加约束，不能删减程序推导的要求。

旧 `MotionDraft` 的 `role + property` 若已经稳定使用，保留内部格式，增加外部 controlId 到该二元组的唯一映射。由服务端请求绑定已有 `rigProfile`、`requirements`、`channels`、`provenance` 等字段，禁止建立互不兼容的第二套播放器。

### 8.3 协议示例

以下为 **EXAMPLE ONLY**：仅说明格式，不对应拉菲，不构成任何真实模型的范围或质量证据。真实请求中的 digest 应为有效内容摘要。

```json
{
  "status": "motion",
  "requestId": "example-request-001",
  "contextId": "example-context-001",
  "profileDigest": "EXAMPLE_ONLY",
  "draft": {
    "schemaVersion": "pliette.motion-draft/1.1",
    "id": "example-small-gesture",
    "durationSec": 1.2,
    "phases": [
      {"name": "prepare", "startSec": 0, "endSec": 0.3},
      {"name": "stroke", "startSec": 0.3, "endSec": 0.9},
      {"name": "recover", "startSec": 0.9, "endSec": 1.2}
    ],
    "curves": [
      {
        "controlId": "arm.right.upper.rotate",
        "keys": [
          {"timeSec": 0, "value": 0, "ease": "smooth"},
          {"timeSec": 0.3, "value": 12, "ease": "smooth"},
          {"timeSec": 0.9, "value": 8, "ease": "smooth"},
          {"timeSec": 1.2, "value": 0}
        ]
      }
    ]
  }
}
```

每条曲线的参考值在请求档案中固定，不是“基于上一个网络请求结果继续累加”。当前合成姿态与第一键不同时，由已登记的入场策略处理并检查；不能直接瞬移到第一键。

### 8.4 默认在线预算

以下是可配置的初始工程预算，不是已测性能或角色生理限制。调整必须进入配置与评测记录，不能在测试失败后无记录地放宽。

| 项目 | 初始值 |
| --- | --- |
| 单片段时长 | 0.4～2.0 秒 |
| 单片段控制器数 | 最多 6 个 |
| 单曲线关键帧 | 2～6 个 |
| 单片段关键帧总数 | 最多 24 个 |
| 自动循环 | 在线输出不支持无限循环；有限循环由现有批准控制器或调度器管理 |
| 生成输出预算 | 建议约 1,536 tokens，并设置 32 KiB 字节上限；截断响应视为失败 |
| 活跃请求 | 每个角色最多 1 个；相同通道的新请求使旧请求过时 |
| 默认请求截止 | 2,500 ms；从请求提交计时，不从首 token 计时 |
| 在线自动修订 | 默认 0 次；实验室最多 3 轮并单独统计 |

参数角速度、位移速度、接触误差等阈值必须来自对应控制器标定，不能从本表推导。片段时长不等于调用周期：静止、呼吸和持续状态复用本地控制，不以每秒固定调用 LLM 维持画面。

网络传输可以使用流式接口，但 V1 只在一整个有限片段接收完整并通过验证后提交播放；不把尚未闭合的 JSON 或先到达的单个关键帧直接写入骨骼。首 token 到达不能算作动作响应。

## 9. 验证、编译和提交播放

### 9.1 验证顺序

1. 验证响应大小、完整性、Schema、请求身份及 profileDigest。
2. 验证角色、视图、Skin、参考姿态与控制器能力；拒绝未知或未开放项。
3. 验证类型、有限数值、时间、阶段、数量、范围、速率和缓动限制。
4. 从控制器和底层时间线计算真实 writes / dependsOn / resources / contacts，检查整组属性及 IK/FK 冲突。
5. 编译为匹配版本的官方动画对象，检查编译后的属性写集，防止转换引入额外写入。
6. 在隔离的官方 skeleton 实例上评估实际曲线和必要组合轨迹；检查最终合成值、接触和可观察效果。
7. 提交前重新读取当前状态，检查陈旧性及入场、退出条件；合格后原子地取得相关控制权并开始播放。

合法关键帧不代表整段轨迹合法。连续标量先检查可计算的极值与速率；组合几何按声明的播放步长采样并检查转场。采样检查不是对所有连续状态的形式化证明，受限在线模式仍要依靠已标定范围、保守组合和运行时守护。

隔离实例应复现当前基础动画、相位、Skin、约束和相关控制状态，不能只在静态 setup pose 上验收叠加动作。未来基础轨迹或接触处理尚未能复现时，先限制在线创作到可验证的稳定基础状态。

### 9.2 入场与恢复也是候选的一部分

检查范围包括混入段、主体段和混出交权段。不能只检查草稿内部的曲线，就让不合法的起始姿态通过 crossfade。

优先复用 Spine 的混合、分层和空动画交权机制；根据目标版本编写适配测试。它们提供播放机制，不会自动保证接触、速度连续或视觉自然。[Spine Applying Animations](https://esotericsoftware.com/spine-applying-animations)

候选结束或取消时，交回当前基础控制器；若有承诺的接触或持物资源，则按现有释放策略处理。不能用直接清轨道、全身归零、清空其他轨道或恢复过时起始快照来结束局部动作。

### 9.3 请求过时与最新状态

维护两类状态：

- **离散版本**：模型、档案、Skin、视图、姿态类、控制权、接触或基础行为发生相关变化时递增。候选依赖的版本改变，拒绝提交并记录原因。
- **连续状态**：动画相位、角度和位置持续变化。不能因为每帧变化而把所有候选判过时；按已登记的入场范围、偏差阈值和过渡策略重新检查。

允许的小偏差只能由已实现并测过的确定性入场策略处理；偏差过大就丢弃候选，不能盲目给所有角度加上当前值。取消后迟到的响应、已切换角色的响应、重复 requestId 都不得再执行。

状态检查与控制权获取必须在同一次调度提交中完成，防止“检查时空闲、执行时已占用”。其他无关通道的变化不应让全部候选失效。

### 9.4 运行时守护和回退

逐帧检查可计算的合成范围、非有限数值和已实现的接触误差。若出现异常，执行受控退出，记录实际播放片段及失败原因。运行时防护不能依靠逐帧截图上传或等待第二个 LLM。

作者候选超界时优先拒绝，不静默裁剪后宣称成功。应急数值限制可以阻止异常传播，但要记为失败并保留原始值。回退选择当前有效基础控制器或已有批准动作，不能覆盖被占用的资源。

若出错时连正常退出都无法满足当前状态，使用项目既有故障恢复策略并明确记录；不要在本轮承诺通用物理安全或零穿模。

## 10. Lab、记录和诊断

### 10.1 最小调试界面

复用 Motion Lab，补充以下实际工作入口，不建设复杂后台：

- 选择角色档案、Skin、视图，查看精简骨架说明和当前开放控制器。
- 单参数探针、固定条件回放、相关骨骼或锚点高亮。
- 查看本次完整请求上下文、生成原文、候选、诊断和最终执行结果。
- 同条件对比原动画、首轮输出、修订输出；支持暂停、逐帧和录屏。
- 查看组合占用、依赖、入场和退出状态，主动触发中断与过时响应。

### 10.2 诊断最低字段

`code / stage / requestId / draftId / controlId / ruleId / expected / actual / affectedTimeRange / recoverable`。缺少相关字段时可省略，不编造数值。错误消息指出实际失败点，如“右手已用于托腮，当前请求不可释放”，而不是统一返回“参数不合法”。

最低错误码：`UNKNOWN_CONTROL`、`UNVERIFIED_CONTROL`、`PROFILE_MISMATCH`、`UNSUPPORTED_VIEW`、`INVALID_VALUE`、`RANGE_VIOLATION`、`RATE_VIOLATION`、`PROPERTY_CONFLICT`、`CONTACT_DEPENDENCY`、`INVALID_TIMELINE`、`STALE_CONTEXT`、`DEADLINE_EXCEEDED`、`OUTPUT_TRUNCATED`、`INSUFFICIENT_CONTEXT`。

### 10.3 可追溯性

每次运行保留：模型服务及可获取版本、采样设置、token 用量或未提供标记、输入输出原文、档案摘要、生成及处理各阶段时间、候选与编译产物摘要、规则命中、是否回退、录像路径、评分与修订链。

不得记录 API 密钥。生成参数、修改 Primitive、改变绑定或改写校验规则是不同事件，必须分别记录。运行时数据不会自动改写正式指导书；经验先作为候选记录，经开发流程验证后发布新档案版本。

## 11. 实验：指导书是否提高首轮质量

### 11.1 三组对照与公平性

| 组别 | 输入和处理 | 回答的问题 |
| --- | --- | --- |
| A：最小接口说明 | 相同控制器列表、类型、单位、参考姿态、标量合法范围、预算、输出 Schema 与状态；不附详细模型经验、组合教学和案例 | 基础接口下的首次生成质量 |
| B：完整指导书 | A 的内容，加角色专属说明、相关组合规则与案例 | 指导知识对同一 LLM 的改善 |
| C：完整指导书 + 程序验证 | **复用 B 的同一个原始输出**，经过正式验证、编译、接续检查与回退 | 程序筛选能挡住什么、付出多少拒绝与延迟代价 |

A 不能故意连参数单位和骨架身份都不给，否则会把基本接口缺失误当成指导书收益。A/B 的请求、状态、可创作控制范围、输出预算及推理设置保持一致，固定档案版本。

A/B 都只在隔离 Lab 中评估，不绕过正式产品的执行边界。可解析候选按同一官方播放器渲染；涉及数值异常的候选直接记失败，不为展示执行危险或不可控值。自动检查结果仍保存，但 B 的原始首轮质量不因 C 的筛选而重新计分。

### 11.2 最小实验规模

优先使用已经配置、预算明确的一种 LLM 服务。每个角色选择 10 条域内请求：6 条基本动作，4 条组合或中断请求；具体动作以资产已验证能力为准。每条 A/B 各独立生成两次，两个角色共 80 次生成；C 复用 B 的输出，不再次调用。

示例候选可包含待机微动、点头、左右小挥手、倾身倾听、收缩姿态，以及挥手叠加另一部位、头身联动、中途中止和非中性姿态接续。托腮、行走、嘴型只有能力存在时才进入域内测试，不为凑数量伪造支持。

另外保留不支持姿态、错角色、占用冲突等负例，用确定性候选和少量指定请求测试。它们与正常动作通过率分开统计。

示例集与测试集分开；测试中至少一半请求为未写进案例的新表达或新组合。在最终评测前冻结 guide 和档案，记录其摘要；看过测试失败后改指导书，就必须登记新版本，并使用新保留集重新评测，不能覆盖旧成绩。

没有足够 API 预算或未提供服务时，允许完成候选导入、录制、校验与本地工程验收；明确标记 LLM 对照和端到端性能未测。开发 Agent 自身生成的文件样本可以检查管线，不冒充目标轻量模型的实时测量。

### 11.3 必须报告的指标

| 指标 | 定义 |
| --- | --- |
| 原始首轮视觉通过率 | 未经参数修订就完成目标且通过视觉门槛的次数 / 全部域内请求次数；格式错误、超时、错误拒绝都计失败 |
| 程序接纳率 | C 中被接纳并实际执行的候选 / 全部域内请求 |
| 实际执行成功率 | 正确完成原请求的生成动作 / 全部域内请求；回退不计成功 |
| 接纳后的质量 | 被接纳候选中视觉通过的比例；必须与接纳率一起给出 |
| 正确拒绝率 | 域外或故意冲突请求被准确拒绝的比例，单独列出 |
| 修改成本 | 首轮、每轮反馈、人工编辑、规则或 Primitive 修改分别统计 |
| 延迟 | 请求到完整响应、验证编译、调度等待、入场开始、达到主要表达分别计时；报告 p50 / p95 |
| 资源开销 | 同一机器开关生成流程的帧时间、主线程占用和内存变化 |

重试后的成功不计入首轮。只提供“播出的动作 100% 合格”却隐藏大量拒绝，视为评测不完整。组 B/C 使用相同输出，因此 C 不应被描述为提高了 LLM 原始生成能力。

### 11.4 视觉和在线开放门槛

沿用旧 Spec 的四项 0～5 评分：部位协调、节奏与重量感、轮廓可读性、角色风格。单项至少 3，平均至少 4，并且目标完成、无明显部件错位、关节反折、姿态瞬移、违背已承诺接触等严重问题，才算视觉通过。评分者和依据必须标明；自动数值评分不能替代观看画面。

本轮的初始在线目标为：在明确列出的角色、视图和动作域内，B 原始首轮视觉通过率至少 90%；C 的全部域内请求中实际生成执行成功率至少 90%；负例中的确定性硬规则不得有漏放；成功生成从提交请求到新动作首次可见变化的 p95 不高于 2,000 ms。2500 ms 为默认请求截止，不是达标延迟。

这些是本项目的候选开放门槛，不是文献结论或本次实测结果。任一门槛未达标，交付真实结果并保留 Lab 或更小动作域；可以保留已可用的 Select/Tune。不得修改统计分母、缩掉失败日志，或将待机回退算作在线创作达标。

跨模型能力必须逐角色报告，不能用总体平均掩盖第二个角色失败。当前样本仅支持初步工程判断，不宣称对任意骨架或任意动作普遍有效。

## 12. 工程测试与录像交付

### 12.1 必需测试

以下测试针对真实风险，用正式编译器、规则解释器及官方运行时验证；不写仅复述配置值的空测试。

| 测试 | 通过条件 |
| --- | --- |
| 档案身份 | 错角色、旧 digest、错误 Skin/视图不能执行 |
| 编译采样 | 参考姿态、符号、单位、关键时刻与缓动中间值按定义到达真实属性 |
| 参数影响 | 改变值会按说明影响最终骨骼、锚点或画面，不被 IK 或其他轨道无意覆盖 |
| 结构差异 | 第二个真实骨架使用自身映射；不存在的自由度准确关闭 |
| 隐含依赖 | 兄弟头身、父级联动、带权重附件、IK/FK、同属性组冲突正确处理 |
| 完整轨迹 | 中间值、混入混出、组合姿态违规可以被对应已实现检查发现 |
| 接触与抢占 | 不破坏受承诺的接触；取消局部动作不清空其他通道 |
| 迟到与重复 | 超时、取消、角色切换后的响应不再播放，requestId 幂等 |
| 最终状态 | 动作退出没有累积漂移、残留覆盖或错误全身复位 |
| 文档一致性 | 修改源规则并重建后，LLM 片段与运行时配置同时更新；旧快照仍不可变 |

本轮新增在线通路连续运行至少 10 分钟，交替请求、取消、切换角色和回退，检查实例、监听器及内存是否持续增长。完整产品原有长时间运行门槛仍按既有规范执行，不在本轮重复无关测试。

### M0：仓库与资产基线

### M1：主角色指导书

完成第 3～6 节的控制档案、探针、有效范围、依赖规则和案例。优先开放少量真正有用的控制器。生成一份可读说明书及其机器配置；主角色的每个开放控制器都有作用证据。

### M2：候选通路与验证

完成上下文装配、MotionDraft V1.1 或兼容映射、严格验证、官方编译、入场退出、诊断、候选文件导入。先通过本地候选和确定性风险用例，再接已配置 LLM。

### M3：受限在线与单角色实验

接入已有模型服务，独立请求异步生成；处理截止、取消、状态变化和回退。完成主角色 A/B/C 结果。修订记录与首轮记录分开，说明未达标原因。

### M4：第二骨架与总验收

为第二角色重新标定并生成专属指导书，验证同一意图在结构差异下的实际参数设计。完成对照、跨角色隔离、录像及逐角色开放范围；按门槛决定是否启用在线 Author。

阶段门槛用于确认事实，不要求每个阶段暂停向用户申请批准。遇到缺失条件继续完成其他已授权工作，并在最终报告列明缺口。

## 14. 研究依据和适用边界

已有 [Real-time Animation Generation and Control on Rigged Models via Large Language Models](https://arxiv.org/abs/2310.17838) 研究让 LLM 输出结构化文本，由引擎形成骨骼动画和状态转换，支持本路线具有研究先例；其演示不等于本项目轻量模型在 Spine 资产上的性能保证。

[Alter3](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2025.1581110/full) 使用关节含义、控制规范和示例，将自然语言动作转换为控制程序，与模型专属指导书的思路接近。Pliette 借鉴显式身体说明，不引入该机器人的控制系统。

[LL3M](https://threedle.github.io/ll3m/) 通过可编辑代码及视觉反馈反复改进建模结果，说明 Agent 的最终建模质量包含执行和修订过程。不能直接将这种能力等同于一次、低延迟的动作参数生成。

[How Much Do Large Language Models Know about Human Motion?](https://arxiv.org/html/2505.21531v1) 在所测试模型和 3D avatar 设置下观察到：结构化引导有助于动作规划，但精确部位定位仍有困难。该结果支持分别评估语义、数值、组合和画面；不直接代表当前 DeepSeek、ChatGPT 或 GLM 轻量模型的表现。

本文的模块边界、协议、实验规模与阈值是针对 Pliette 的设计决策。实现时以真实资产、锁定版本的官方 API、可复现渲染和测量为依据；不把文献结论或旧 PoC 转述成新测试成绩。
