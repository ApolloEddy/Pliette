# 研究笔记：如何做好"实时生成动作"

日期：2026-09-08 · 状态：思考文档（待讨论定案，未立项）

## 1. 先把问题问对

"实时生成动作" ≠ "LLM 实时从零生成关键帧"。我们用两轮被否决的实验买到了这个区分：

- 生成关键帧 = 在"好动作"的高维稀疏空间里盲采样。质量藏在动画师手调的节奏、缓动性格、多部位相位差、跟随摆动里——这些不在骨骼名和参数域中，推不出来。
- **行业已验证的"实时生成"形态是另外的东西**：专业片段的组合与过渡（motion matching / motion graphs，代表作：《For Honor》《漫威蜘蛛侠》的动画系统）+ 程序化细节层。质量由资产保证，实时由架构保证，多样性由图遍历保证。

我们的实验恰好证明了这两半：
- 专业切片叠加 = 零迭代达标（晕眼/摸头/指向全部立即成立）
- 生成数值 = 多轮仍不达标

## 2. 五条候选路线（按可信度排序）

### 路线 1：动作图（Motion Graph）——核心推荐 ★

**思想**：把 20 段专业动画自动切分成带标注的片段（挥手、伸懒腰、低头、弯腰……我们已有世界坐标勘探器），在片段边界寻找姿态相似点连成转移图；运行时按行为目标在图上游走，转移处用官方混合交叉淡化。

- 产出：**"无限不重复的待机/动作流"**——她永远不会精确重复自己，但每一段都是专业数据
- 实时性：图遍历 + crossfade，每帧成本≈0（现有 AnimationState 混合直接支持）
- 已有地基：勘探脚本（mine-world-segments）、切片播放（overlay.ts 的 animationStart/End 时间窗就是图边的实现原型）、通道过滤
- 成本：切分质量需要目视迭代（边界处的混合自然度是主要打磨点）；预计 1-2 天出第一个"20 分钟不重样的待机"demo
- 风险：转移点选择不佳会导致动作"跳跃感"——需要相似度度量（骨架姿态距离）+ 目视校准

### 路线 2：程序化生命层（辅助，小步验证）

呼吸不规则化、重心微移、头发/裙摆的弹簧物理（spring-damper 驱动骨骼链，在 AnimationState.apply 之后叠加）。

- 收益：给所有状态加"活物感"，掩盖循环感
- 风险：专业动画里已经烤入了部分跟随摆动——叠加前必须先测量，避免双重摆动（Spec 10.3 原则）
- 成本：小；逐条链验证

### 路线 3：LLM 编舞（Choreographer）——已半建成

LLM 不生成动作，生成"演出脚本"：给定对话与情境，输出节拍化的表演计划（何时挥手、何时不悦、何时凑近），运行时用路线 1 的图 + 通道叠加执行。

- 现状：EVENT_RECIPES + 调度器 + Select 层已是雏形；升级方向是"节拍时序"而非"单点触发"
- 质量与 LLM 解耦——它只做它可靠的事

### 路线 4：离线人机共创扩充库（增长回路）

需要全新类型的动作（现有 20 段覆盖不到的）时：LLM 起草 → 用户在 Spine 编辑器制作/修改 → 入库。实时压力解除后，生成质量要求大幅下降；库以人工把关的方式增长。

### 路线 5：学习式生成（in-betweening/动作扩散）——明确搁置

在 Q 版 2D 骨架上训练需要大量同风格专业数据（我们只有 1 个角色 20 段）；跨骨架迁移又被 Spec 排除。触发条件：未来积累多个同管线角色资产后再评估。

## 3. 建议的验证顺序

1. **动作图 PoC**（路线 1）：自动切分 stand → 建图 → "20 分钟不重样待机" demo → 用户目视验收
2. 通过后：接入行为层（LLM 编舞/事件配方驱动图遍历）
3. 并行小步：程序化生命层逐链实验（先测冲突再叠加）
4. 路线 4 作为库增长的常态机制；路线 5 搁置

## 4. 与现有架构的关系

不需要推翻任何东西：动作图是 overlay/gesture 机制的升级版（片段来源从"手工挑选"变成"自动勘探+图遍历"），调度器/Select 层/接触锚点全部复用。这符合 Spec 1.2 的长期路线："Spine 原生动画能力 + 参数化动作预置 + 属性级组合调度"。

## 5. 诚实的边界

- 动作图能保证"专业质量的连续变化"，但**造不出库里没有的动作类型**——新类型仍走路线 4（人工制作入库）
- 仅正面资产的限制不变（转身、背面交互仍然缺位）
- 转移自然度的打磨是主要工作量，且必须目视验收（又是"看"的问题——但这次看的是过渡点，比看整段生成动作的目标小得多）
