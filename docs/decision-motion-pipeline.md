# 技术决策：动作管线中 LLM 的角色定位

日期：2026-09-08 · 状态：**已定案（用户签收）**

## 决策

**放弃"LLM 实时生成动作参数"路线；LLM 角色定位为行为选择层（Select），动作数据全部来自专业资产。**

## 依据（P1 对照实验数据）

| 路线 | 迭代成本 | 质量结果 |
| --- | --- | --- |
| LLM/Agent 生成稀疏关键帧 | 6 项 × 多轮修订（Tune+Author 两种模式） | 两轮用户否决：单部位僵直、幅度不可读、整体不达标 |
| 原动画切片复用（overlay） | 一次勘探、零迭代 | 全部立即达标：挥手/螺旋晕眼/被摸头/低头/指向（见 `experiments/media/p1/overlay-*.mp4`） |

结构性原因：Q 版动作的质量来源是动画师手调的节奏、挤压拉伸、跟随摆动与多部位协调，这些无法从"骨骼名 + 参数域"由 LLM 推导。实时逐次生成的延迟与质量风险在此基础上再叠加。

## 按 Spec 14 P1 退出条款执行

"若多轮后仍无法稳定产出可用动作，保留播放器与数据结构，改为复用优质原动画、由 Agent 辅助小范围调节和少量专用制作"——已执行：

- **保留**：官方运行时接入、RigProfile、编译器/Schema（作为有界调制的地基）、调度器、通道叠加架构、全部勘探与验收工具链
- **动作库**：拉菲 20 段原动画 + 手势切片库（`gestures.ts`，世界坐标勘探提炼）
- **LLM 运行时角色（Select 模式，Spec 2.2）**：语境理解 → 事件 → 行为配方（`EVENT_RECIPES`：greet→wave、praise→pump+happy…）→ 从库中选择、填有界参数（时机/表情变体/朝向/hand auto）。动作质量与 LLM 解耦

- A02 用例按"已终止"记录（`acceptance-checklist.md`）
