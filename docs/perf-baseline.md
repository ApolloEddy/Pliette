# 实时性能基线（P1 阶段实测）

测量：2026-09-07 · 工具：`scripts/bench-realtime.mjs`（CDP 驱动，真实计时，非虚拟时间）· Lab `?bench=1` 模式

## 结论

**实时交互没有瓶颈。** 桌面伴侣产品的每帧成本（Spine 更新+绘制 → CanvasTexture 上传 → Three.js 场景渲染）在**无 GPU 的软件渲染**下平均不到 0.5ms；帧间隔 p95 = 4.3ms，远低于 Spec 15.4 的 20ms 上限。60 FPS 目标有 2.5 倍以上余量（真机 RTX 4060 + GPU 光栅化只会更快）。

| 场景（完整产品路径） | 平均 FPS | 帧间隔 p50/p95 (ms) | 整帧渲染 avg (ms) |
| --- | --- | --- | --- |
| lafei_8 原始贴图（1024×256） | 168.3 | 4.2 / 4.3 | 0.478 |
| lafei_8 超分 3x 贴图（3072×768） | 195.0 | 4.2 / 4.3 | 0.455 |

- 平面基线模式的裸 Spine 绘制路径：106.5 FPS（p95 12.6ms），同样达标。
- max ≈ 230-245ms 为页面加载首帧毛刺，非稳态；稳态无卡顿。
- 采样 6 秒真实时间、1010-1170 帧，walk 动画循环播放的完整工作负载。

## 与"视频渲染几分钟"的关系（重要澄清）

P1 视频证据管线（`scripts/capture-p1-video.sh`）每帧都要**冷启动一个 headless 浏览器**（约 3-4 秒/帧），这是为确定性对照证据设计的离线流程（Spec 15.3 允许离线逐帧导出，但明确其不能作为实时帧率证据）。**产品运行时与该流程完全无关**：一个常驻浏览器/Electron 进程，每帧就是一次 Spine 求解 + 纹理上传 + 场景绘制（上表数字）。

## 超分贴图结论

用户提供的 `lafei_8-upscale-3x.png`（3072×768，3 倍超分）经 atlas 坐标缩放加载后：

1. **渲染正确**：姿态与原始贴图逐像素对位（A/B 截图核对），无错位；
2. **清晰度提升可见**：发丝/眼睛高光/猫伴细节更锐利；
3. **零性能代价**：完整路径 FPS 不降反稳（纹理上传 ~9MB/帧 @60fps ≈ 560MB/s，对目标 GPU 可忽略）。

Lab 资产下拉已提供「拉菲 lafei_8（超分 3x）」条目（`textureScale: 3`，`scaleAtlasText` 自动缩放 atlas 坐标）。

## 边界

- 本基准为 headless 软件渲染（SwiftShader），是**下界**；目标机器（RTX 4060 / 1080p 窗口 / Electron）的正式验收按 Spec 15.4 在 P4 阶段以真实环境测量并记录 CPU/GPU/内存。
- p95 处的持续帧间隔分布、30 分钟长跑内存泄漏检查、纹理实例增长监测留待 P4。
